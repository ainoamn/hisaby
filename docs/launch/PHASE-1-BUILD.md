# المرحلة 1 — البناء والاعتماديات

التاريخ: 1 نوفمبر 2026  
الحالة: لم تُقبل. المرحلة 2 لا تبدأ قبل إغلاق فجوة الترحيل من قاعدة فارغة.

## ما ثَبت

- `prisma validate` و`prisma generate` على Prisma 5.22.0 بعد حذف علاقة `User.bhdRInboundEvents`. لا يوجد ترحيل SQL لأن العلاقة لم يكن لها عمود.
- `npm run type-check` في الخادم والواجهة بلا أخطاء. أخطاء TypeScript 5.9 في SSO وتكامل BHD R أُصلحت دون تغيير سلوك الطلبات.
- `npm run build` في الخادم نجح. `npm run build` في الواجهة نجح على Next 15.5.28.
- Jest في الخادم: 23 مجموعة و75 اختبارًا، وكلها نجحت. منها `commercial-scope.spec.ts`. Jest في الواجهة: اختبار واحد نجح.
- فحص الحزم بعد الرفع داخل الجيل نفسه موثّق في `DEPENDENCY-ADVISORIES.md`. بوابة `scripts/audit-gate.mjs` نجحت في الخادم والواجهة، وتبقي استثناءين مكتوبين فقط.
- صورة الواجهة أصلًا تنسخ مخرجات `standalone` ولا تنسخ `node_modules` كاملة. صورة الخادم صارت تبني طبقة `proddeps` بـ`npm ci --omit=dev` ثم تولّد عميل Prisma. لم يُبنَ صورة Docker في هذه الجولة.
- `COMMERCIAL_SCOPE` غير مضبوط، لذلك مسارات الإنتاج الحالية لا تُغلق. الإغلاق يحدث فقط عندما تُضبط القيمة `v1`.

## ما منع القبول

تشغيل `prisma migrate deploy` على PostgreSQL 16 فارغ ومعزول فشل عند `20260721201000_employee_claims`:

`relation "employees" does not exist`

جدول `employees` موجود في `schema.prisma` وتشير إليه هذه الترحيلة، ولا توجد ترحيلة تنشئه. قاعدة التجربة حُذفت بعد الفشل. لم تُمس قاعدة الإنتاج.

تعديل SQL ترحيلة مطبّقة سابقًا يغيّر المجموع الرقابي ويفشل `migrate deploy` على القاعدة الحالية. لذلك لم يُعدَّل السجل التاريخي، ولم تُضف ترحيلة جديدة في آخر السجل لأن الفشل يحدث في الوسط ولا يصل التنفيذ إلى آخره.

النسخة «السابقة الشكل» لم تُختبر لأن إعادة التشغيل تتوقف قبل اكتمال القاعدة الفارغة.

CI الحالي لا يشغّل PostgreSQL. لم يُدفع هذا الفرع، فلم تُعاد جولة GitHub.

## قرار

لا يُقبل الإطلاق، ولا تبدأ المرحلة 2، قبل اختيار إصلاح للسجل لا يكسر القاعدة القائمة. الخيارات التي تحتاج قرار المالك:

1. ترحيلة إصلاح تُدرج قبل `employee_claims` في القواعد الجديدة فقط، مع إبقاء المجموع الرقابي للإنتاج كما هو. هذا يحتاج مسار baseline منفصل، لا تعديلًا صامتًا لترحيلة مطبّقة.
2. تأكيد شكل جدول `employees` في الإنتاج، ثم كتابة إنشاء متوافق معه للقواعد الجديدة.

حتى ذلك يبقى البيع والتسجيل العام والدفع مغلقين.
